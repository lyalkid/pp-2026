# Как выпустить новую версию

Эта инструкция для тех, кто поддерживает проект и выпускает релизы.

Релиз — это отметка в истории проекта: «вот эта версия готова, её можно скачивать». На GitHub каждый релиз появляется на вкладке **Releases** с описанием и архивом кода.

## 1. Выберите номер версии

Посмотрите, что лежит в разделе `[Unreleased]` в [CHANGELOG.md](CHANGELOG.md):

- только исправления (`Fixed`) → увеличьте последнюю цифру: 1.2.0 → **1.2.1**;
- есть новые возможности (`Added`) → увеличьте среднюю цифру: 1.2.0 → **1.3.0**;
- что-то сломалось для старых пользователей (например, поменялась структура базы и старый `database.db` не подходит) → увеличьте первую цифру: 1.2.0 → **2.0.0**.

## 2. Обновите CHANGELOG.md

Было:

```
## [Unreleased]

### Added
- Немецкий язык интерфейса.

## [1.2.0] - 2026-09-30
```

Стало:

```
## [Unreleased]

## [1.3.0] - 2026-10-15

### Added
- Немецкий язык интерфейса.

## [1.2.0] - 2026-09-30
```

То есть раздел `[Unreleased]` остаётся пустым, а всё из него переезжает под новую версию с сегодняшней датой.

Внизу файла обновите ссылки:

```
[Unreleased]: https://github.com/lyalkid/simple-posts/compare/v1.3.0...HEAD
[1.3.0]: https://github.com/lyalkid/simple-posts/compare/v1.2.0...v1.3.0
```

## 3. Обновите номер версии в README.md

В начале README есть строчка `Текущая версия: **1.2.0**`. Поменяйте на новую.

## 4. Сделайте коммит

```
git add CHANGELOG.md README.md
git commit -m "Release v1.3.0"
git push
```

## 5. Поставьте тег

Тег — это «закладка» на конкретный коммит с названием версии.

```
git tag v1.3.0
git push origin v1.3.0
```

## 6. Создайте релиз на GitHub

1. Откройте репозиторий на GitHub.
2. Справа нажмите **Releases**, потом **Draft a new release** (или **Create a new release**).
3. В поле **Choose a tag** выберите `v1.3.0`.
4. В **Release title** напишите `v1.3.0`.
5. В описание скопируйте раздел этой версии из CHANGELOG.md.
6. Нажмите **Publish release**.

Готово. GitHub сам приложит к релизу архивы с кодом.
